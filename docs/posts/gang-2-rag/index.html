Gang 2 — Retrieval Augmented Generation (RAG)

rag dify embeddings llm

What is RAG?

A plain LLM only knows what was in its training data. RAG — Retrieval Augmented Generation — extends that by giving the model a live knowledge source to search at query time. The flow is:

User question → embed question → search vector store → retrieve top-k chunks → inject into prompt → LLM answers

This solves two problems: the model can answer questions about documents it never trained on, and it can cite specific passages rather than hallucinating a plausible-sounding answer.

RAG makes most sense when the source material changes often, is private, or is too large to fit in a single prompt. It's less useful for general reasoning tasks where the model's training knowledge is already sufficient.

Three Approaches We Compared

ChatGPT CustomGPT

✓ Zero setup, familiar UI

✗ Locked into OpenAI
✗ Limited control over retrieval

customGPT.ai

✓ Easy embedding widget

✗ Paid from the start
✗ Black-box retrieval

Dify.ai

✓ Open source option
✓ Full pipeline control

✗ More moving parts
✗ Steeper learning curve

We chose to implement with Dify.ai for the hands-on part. It exposes the full RAG pipeline — chunking strategy, embedding model, retrieval settings — which makes it easier to understand what's actually happening under the hood.

What We Built

We built a chatbot that answers questions about our studieordning (programme regulations). The document is dense, PDF-formatted policy text — exactly the kind of thing nobody wants to search through manually.

Preparing the data

Before uploading, we converted the PDF to Markdown. Raw PDF extraction is noisy: headers get merged with body text, tables break, and page numbers end up mid-sentence. Markdown gives the chunker clean boundaries to work with, which improves retrieval quality.

Chunking and indexing

Dify split the document into overlapping chunks and ran each through an embedding model to produce a vector representation. These vectors are stored in a database and searched at query time using cosine similarity.

The chatbot

With the knowledge base connected, the chatbot retrieves the most relevant chunks for each question and includes them in the prompt. The system prompt constrains the model to only answer based on the provided document — reducing hallucination and keeping responses on-topic.

Reflection

The most interesting part wasn't the chatbot itself — it was seeing how much the quality of the data preparation mattered. The same question asked against the raw PDF and the cleaned Markdown returned noticeably different answers. Garbage in, garbage out applies to retrieval just as much as it does to training.

The comparison between the three tools also highlighted a real trade-off: ease of use versus control. CustomGPT takes five minutes and works, but you're trusting a black box. Dify takes longer to configure but you can actually debug why a retrieval failed. For a production system I'd lean toward the more transparent option — bugs in a RAG pipeline are subtle and hard to catch if you can't inspect the retrieved chunks.
